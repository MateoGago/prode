# Next.js 16 — Verified API Notes

Read from `node_modules/next/dist/docs/` on 2026-05-27.
Every entry below is a divergence from common Next.js 13/14/15 knowledge.
This file is the gate for REQ-XCUT-2 — do NOT implement routes or the proxy
until you have verified the relevant item here.

---

## 1. Middleware → Proxy (BREAKING rename in v16.0.0)

**What changed**: The file `middleware.ts` / `middleware.js` is deprecated and
renamed to `proxy.ts` / `proxy.js`.

**Location**: `src/proxy.ts` (inside `src/`, same level as `app/`).

**Export**: Named `proxy` export (or default export). The old `middleware` named
export is deprecated.

```ts
// src/proxy.ts
import type { NextRequest } from "next/server";
import { NextResponse } from "next/server";

export function proxy(request: NextRequest) {
  // optimistic session refresh + redirect for unauthenticated users
  return NextResponse.next();
}

export const config = {
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico).*)"],
};
```

**Runtime**: Proxy defaults to **Node.js runtime**. The `edge` runtime is NOT
supported in `proxy`. Do NOT add `export const runtime = 'edge'` — it throws.

**Key constraint**: Proxy is for optimistic checks and redirects ONLY. It must
NOT be used as the authorization boundary. Real auth lives in:
1. `(game)/layout.tsx` → `getUser()` server-side on every render.
2. Supabase RLS policies (`now() < kickoff_at`, admin role).

**Source**: `docs/01-app/01-getting-started/16-proxy.md`,
`docs/01-app/03-api-reference/03-file-conventions/proxy.md`,
`docs/01-app/02-guides/upgrading/version-16.md`.

## 2. Async Request APIs (BREAKING in v16 — synchronous access removed)

These APIs are now async-only. `await` is **required**:

- `cookies()` → `const cookieStore = await cookies()`
- `headers()` → `const headersList = await headers()`
- `draftMode()` → `const draft = await draftMode()`
- `params` in `layout.js`, `page.js`, `route.js` → `const { id } = await params`
- `searchParams` in `page.js` → `const query = await searchParams`

The synchronous compatibility shim from v15 is **fully removed** in v16.

**Impact for prode**:
- Route handlers (`app/api/cron/ingest/route.ts`) must `await params`.
- Auth callback (`app/auth/callback/route.ts`) must `await` cookies/headers.
- `(game)/layout.tsx` must `await params` if accessed.
- Use the `PageProps<'/path/[param]'>`, `LayoutProps`, `RouteContext` helpers
  from `next typegen` for type-safe async params.

**Source**: `docs/01-app/02-guides/upgrading/version-16.md` §Async Request APIs.

## 3. Server Actions / Server Functions — Terminology and Signatures

**Terminology**: "Server Actions" are now called **Server Functions** in the
docs. A Server Action is a Server Function used in a mutation/form context.

**Directive placement**:
- File-level: `'use server'` at top of file → all exports are Server Functions.
- Inline: `'use server'` inside an async function body (valid in Server Components).

**Signature is unchanged** from v14/v15 — still receives `FormData` when wired
to a `<form action={fn}>`.

**New cache API used in Server Actions**:
- `revalidateTag(tag, cacheLifeProfile)` — second arg is NOW REQUIRED (e.g. `'max'`). Single-arg form is deprecated.
- `updateTag(tag)` — new Server-Action-only API for read-your-writes semantics (immediate invalidation + refresh). Use for predictions save.
- `refresh()` from `next/cache` — refreshes the client router from a Server Action.

**Source**: `docs/01-app/01-getting-started/07-mutating-data.md`.

## 4. Route Handlers — Signatures and Caching

**Signatures are unchanged**: `GET(request: Request)`, `POST(request: Request)`, etc.

**Typed context with RouteContext helper** (generated by `next typegen`):
```ts
import type { NextRequest } from "next/server";
export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params;
  return Response.json({ id });
}
```

**Caching**: Route Handlers are NOT cached by default. Only `GET` can opt into
caching via `export const dynamic = 'force-static'`.

**Cron route** (`app/api/cron/ingest/route.ts`): Export a `GET` handler. Protect
with `CRON_SECRET` header check. Do NOT add `force-static`.

**Source**: `docs/01-app/01-getting-started/15-route-handlers.md`.

## 5. PWA Manifest — `app/manifest.ts`

Built-in via `app/manifest.ts` (special cached Route Handler). Return type is
`MetadataRoute.Manifest` (imported from `next`).

```ts
// src/app/manifest.ts
import type { MetadataRoute } from "next";

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: "Prode Mundial 2026",
    short_name: "Prode",
    start_url: "/",
    display: "standalone",
    theme_color: "#...",
    background_color: "#...",
    icons: [
      { src: "/icon-192x192.png", sizes: "192x192", type: "image/png" },
      { src: "/icon-512x512.png", sizes: "512x512", type: "image/png" },
    ],
  };
}
```

**Source**: `docs/01-app/03-api-reference/03-file-conventions/01-metadata/manifest.md`.

## 6. Service Worker — Manual `public/sw.js`

No built-in SW. Register manually with a `'use client'` component mounted in
root layout:

```tsx
// src/app/sw-register.tsx
'use client'
import { useEffect } from "react";

export function SwRegister() {
  useEffect(() => {
    if ("serviceWorker" in navigator) {
      navigator.serviceWorker.register("/sw.js", { scope: "/" });
    }
  }, []);
  return null;
}
```

Mount in `src/app/layout.tsx`:
```tsx
<body>
  <SwRegister />
  {children}
</body>
```

The SW file lives at `public/sw.js`. For offline caching, Serwist requires
webpack config (out of scope for v1).

**Source**: `docs/01-app/02-guides/progressive-web-apps.md`.

## 7. Turbopack by Default in v16

`next dev` and `next build` use Turbopack by default. No `--turbopack` flag
needed. The `--webpack` flag opts out.

**Impact for prode**: `vitest.config.ts` is separate from Next's bundler so no
conflict. The `next.config.ts` must NOT have a `webpack()` function unless
opting out of Turbopack with `--webpack`.

**Source**: `docs/01-app/02-guides/upgrading/version-16.md` §Turbopack by default.

## 8. `next lint` Command Removed

`next lint` is removed in v16. We use Biome directly (`biome check`). Already
handled in `package.json`. No action needed.

## 9. React 19.2 Features Available

- `ViewTransition` — animate elements inside a Transition or navigation.
- `useEffectEvent` — extract non-reactive logic from Effects.
- `Activity` — render hidden UI with `display: none` while maintaining state.
- React Compiler (stable, opt-in via `reactCompiler: true` in `next.config.ts`).

None of these are required for prode MVP; noting for future slices.

## 10. `revalidateTag` Signature Change (Breaking)

```ts
// v15 — single arg (still worked)
revalidateTag("posts");

// v16 — second arg required
revalidateTag("posts", "max"); // or another cacheLife profile
```

For immediate expiry in Server Actions, use `updateTag("posts")` instead.

## Summary — What Changed vs Training Data

| Feature | Training Data (v13/v14) | Next.js 16 Reality |
|---|---|---|
| Middleware file | `middleware.ts` | `proxy.ts` (RENAMED) |
| Middleware function | `export function middleware()` | `export function proxy()` |
| Proxy runtime | Edge (default) | Node.js (always — edge removed) |
| `cookies()` | Sync | `await cookies()` (async only) |
| `headers()` | Sync | `await headers()` (async only) |
| Route `params` | Sync | `await params` (async only) |
| `revalidateTag` | Single arg | Two args required |
| Turbopack | Opt-in flag | Default for dev + build |
| `next lint` | Built-in command | Removed — use Biome/ESLint |
| Manifest | `public/manifest.json` | `app/manifest.ts` (built-in) |
| Service Worker | Same | Manual `public/sw.js`, no change |
| Server Actions | Stable since v14 | Now called "Server Functions" |
